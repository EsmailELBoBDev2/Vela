# نسخة ملفات بيئة كايرو درايف والبحث

اكتمل رفع لقطة ملفات `/workspace` والتحقق منها: **٤٢٥ جزءًا، ١٤٬١٠١٬٤٧٠٬١٩٩ بايت مضغوطًا (نحو ١٣٫١٣ جيبيبايت)، ٦٣٣٬٧٠٥ مسار ملف أو وصلة ملف و٦٣٦٬٨٣٥ مسارًا مع المجلدات والروابط الرمزية**. عدد سجلات الأرشيفات ٦٣٨٬٥٦٧، ويشمل نسخ التحديث المتكررة. أحدث التقاط في ٢٠٢٦-١٠-١٣ الساعة ١٩:٣٨:٣٦ بتوقيت UTC. هذه لقطة مؤرخة، لا تشمل تلقائيًا نتائج البحث اللاحقة ولا تعني اكتمال تحليل التطبيقات.

تشمل المدخلات الأصلية وجميع APKs المقدمة، نتائج استخراج الكود والموارد والأصول والاستعادة والأدلة، قوائم التغطية والمتبقي ونقاط الحفظ والهدف، المشاريع Vela وCairoDrive وOsmand وCoMaps وOrganic Maps وREA، تاريخ Git المتاح في ١٣ حزمة مستقلة، الأدوات وإصلاحاتها وAndroid SDK وJava واعتمادات وكاش ملفات العمل. محفوظ كل ملف جديد أو متغير فوق المجموعات السابقة، ولا يحذف استثناء بيانات الدخول صنف JADX لمجرد أن اسمه `auth.json`. أُعيدت عشرة ملفات ثبت أنها كود مفكوك أو ملفات عامة مطابقة للمصدر؛ الشهادات العامة داخل APK محفوظة أصلًا.

مستثناة بيانات الدخول وحالة جلسات النموذج وسجلاتها، ومفتاح التوقيع المحلي `.android/debug.keystore`. مجلدات تجهيز النسخ واختبار استردادها المكررة والعمليات والملفات غير العادية ليست بيانات مشروع إضافية. هذه ليست صورة نظام تشغيل أو ذاكرة عمليات حية. تفاصيل الاستثناءات والتصحيحات والروابط النظامية الست في `manifests/workspace-audit.json`. ملفات المشروع الأصلية وفرع `main` لم تتغير.

## التحقق

نُزّل كل جزء من GitHub وطابق حجمه وبصمته SHA-256. فُحصت كل محتويات الأرشيفات: المجموعات الأساسية محليًا مع إثبات تطابق بايتاتها البعيدة، والإضافة وتحديثها النهائي بالكامل مباشرة من GitHub. استُعيدت Vela وCairoDrive فعليًا في مجلد اختبار منفصل مع تاريخ Git عند الالتزام الأصلي وشجرتَي عمل نظيفتين؛ واختُبرت جميع حزم التاريخ الثلاث عشرة داخل مستودع فارغ. الأدلة الكاملة في `manifests/complete-backup-verification.json` وتقارير المجموعات واختبار استرداد المصدر. قوائم الملفات وبصماتها في `manifests/*-files.jsonl.gz`؛ ترتيب الاسترداد في `snapshot-index.json`.

أثبتت قراءة كل ملف ثباته أثناء الالتقاط. استمر البحث أثناء النسخ، لذلك ليست اللقطة معاملة متوقفة للجهاز كله؛ راجع نقاط الحفظ وأعد بناء مشروع أداة من APK الأصلي إذا ظهرت مشكلة اتساق قاعدة بيانات حية.

## الاسترداد

وفر نحو ٦٠ جيجابايت أو أكثر في جهاز Linux متوافق، وGit وبايثون حديثًا. النسخة تستخدم Git العادي بأجزاء لا تتجاوز ٣٢ ميبيبايت، وليست مؤشرات LFS. رفض GitHub كائنات LFS الجديدة للفرع المشتق العام؛ ثم تعذر إنشاء مستودع مستقل ورفع أصول إصدار بالمصادقة الحالية، فنجح بديل Git العادي المحقق. وافق المستخدم صراحة على النشر بينما المستودع عام؛ لا تمنح النسخة ترخيصًا لإعادة استعمال الكود المغلق.

```bash
git clone --branch research-backup --single-branch https://github.com/EsmailELBoBDev2/Vela.git cairodrive-workspace-backup
cd cairodrive-workspace-backup
python3 scripts/restore_backup.py --verify-only
python3 scripts/restore_backup.py --destination /workspace-restored
python3 /workspace-restored/workspace-environment/git-restore.py /workspace-restored
```

اختر مجلدًا جديدًا فارغًا؛ لا تسترد فوق البيئة الحالية. تُسترد المجموعات بالترتيب تلقائيًا ويأتي `workspace-final-overlay` أخيرًا. الاسترداد يعطّل تشغيل العمال ويحفظ أرقام العمليات والمحادثة القديمة كتاريخ. أدخل بياناتك بالطريقة الرسمية ثم أنشئ فريقًا جديدًا من ثلاثة وكلاء ومشرف بعد مراجعة الهدف ونقاط الحفظ والقوائم والأقفال؛ لا تعتمد على معرفات عمليات أو جلسات الجهاز القديم.

للاسترداد المطابق لمسارات البرامج الأصلية استخدم `/workspace` فارغًا في جهاز جديد، بدل الكتابة فوق بيئة تعمل. جرد النظام والإصدارات محفوظ في `workspace-environment`؛ البرامج داخل البيئات الافتراضية تحتاج Python 3.12 والنظام والمكتبات المتوافقة. عند وجود أهداف الروابط النظامية الموثقة، يضيف خيار `--restore-system-links` إعادة الروابط الست. إذا اختلف النظام أعد تجهيز البيئة الافتراضية من الاعتمادات المحفوظة بدل الاعتماد على مسارات النظام القديم. أصل APKs والكود والنتائج مستقل عن استعادة العمليات أو حساب النموذج.
